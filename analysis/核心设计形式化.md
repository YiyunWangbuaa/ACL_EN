# 核心设计形式化

> 本文形式化项目核心设计：数据集设计、数据生成程序设计、故障诊断设计、关键环节。目标是 LLM 工程推理的**契约条件化过程级评测**。

---

## 1. 数据集设计

### 1.1 任务分解：契约、骨架、目标

一道工程任务分解为三元组：

\[
\mathcal{T}=(x,c,G)
\]

- \(x\)：物理场景（飞机模型、相机布置、机械臂构型）；
- \(c\)：工程契约（坐标轴指向、角度正方向、变换约定、旋转顺序、安装方式、符号约定）；
- \(G=(V,E)\)：逻辑骨架，节点 \(v\in V\) 是一个待回答步骤或答案字段，边 \((u,v)\) 表示 \(v\) 使用 \(u\) 的输出。

**核心设计：契约与逻辑骨架分离。** 对同一场景和骨架，可系统改变契约字段而不必重写推理流程：

\[
\mathcal{T}_c=(x,c,G),\qquad c=(c_1,\dots,c_K).
\]

契约作为实例输入的一部分：既进入模型提示，也进入参考执行程序。

### 1.2 推理图与测点

每个参考流程表示为带契约条件的有向图：

\[
G_c=(V,E,\{\varphi_v\}_{v\in V})
\]

其中 \(V\) 是答案节点集；\(E\subseteq V\times V\) 是推导依赖边，\((u,v)\in E\) 表示 \(v\) 的推导直接使用 \(u\) 的输出；\(\varphi_v\) 是节点 \(v\) 在契约 \(c\) 下的局部规则。

按能力维度把测点分四类（对应 §3.1 的故障类）：

| 测点类 | 暴露的能力 | 故障类 |
| --- | --- | --- |
| 契约识别测点 | 读对契约（直接识别 + 推理理解） | DIR / RSN |
| 契约执行测点 | 把认出的契约写进对象 | EXE |
| 数理应用测点 | 对已写好的量做计算 | ALG |
| 目标问题 | 上述能力综合 | — |

测点 \(m=(v_m,\pi_m,g_m,\varphi_{v_m})\) 可对应整个节点，也可对应节点答案的字段（矩阵元素、向量分量、外层符号、力臂、分子分母）。字段级测点把能直接反映契约执行失败的关键错误模式（符号反转、特定位置的元素形式）分离出来，使局部选择可直接观测。

### 1.3 四个领域

| 领域 | 节点 | 覆盖的工程契约 |
| --- | ---: | --- |
| 风洞空气动力学 | 207 | 坐标约定、姿态变换、力/力矩轴向 |
| 飞行力学 | 131 | 气动量与载荷换算 |
| 机器视觉 | 66 + 165 | 位姿、双目几何 |
| 机器人运动学 | 156 | 齐次变换、运动学求解 |

（flight_ctrl、wind_arm 为未迁移的生成器壳。）

## 2. 数据生成程序设计

### 2.1 确定性生成程序

三个功能模块：

1. **契约实例化器**：\(c\) → 题面中的工程定义与方法要求；
2. **骨架生成器**：\((x,G)\) → 逐步问题及依赖；
3. **契约条件化执行器**：在 \(c\) 下沿骨架执行局部规则，生成金标轨迹。

局部计算规则依赖契约与父节点值：

\[
g_v=\varphi_v(g_{\mathrm{Pa}(v)},x,c).
\]

金标轨迹与目标量：

\[
\tau^\star=(g_{v_1},\dots,g_{v_{|V|}}),
\qquad
y^\star=\mathrm{Target}(\tau^\star).
\]

题面、金标、目标统一由 \(q=\mathrm{Gen}(x,c,G)\)、\(\tau^\star=\mathrm{Exec}(x,c,G)\) 生成。

### 2.2 契约组合实例化

契约组合空间 \(\Theta\subseteq\mathcal{C}_1\times\cdots\times\mathcal{C}_K\)，每个 \(\theta\in\Theta\) 生成：

\[
q_\theta=\mathrm{Gen}(x,\theta,G),\qquad \tau^\star_\theta=\mathrm{Exec}(x,\theta,G).
\]

保持物理实体与目标不变、只改契约，生成**结构可比、契约不同**的评测实例。金标不是从标准答案变换得到的标签，而是该契约条件下完整执行骨架的结果。

### 2.3 两层计算与契约认知重构

确定性程序包含两个层级的计算：

- **金标层**：用金标父节点、正确契约 \(c\) 执行 \(\varphi_v\)，输出自洽标准结果；
- **局部计算层**：用模型实际父节点、模型认知契约 \(\hat{c}\) 执行 \(\varphi_v\)，输出模型前缀下的条件结果。

**契约认知重构。** 局部计算层不直接按正确契约执行父节点，而是先从模型在识别测点（DIR/RSN）上的回答重构出模型实际认知到的契约 \(\hat{c}\)（例如由模型写下的坐标轴三元组推断其认知的手性，而非读金标的 chirality），再在 \(\hat{c}\) 下执行 \(\varphi_v\)：

\[
\tilde{o}_v=\varphi_v(o_{\mathrm{Pa}(v)},x,\hat{c}).
\]

这样才能区分「识别错」（\(\hat{c}\ne c\)，模型忠实执行了错误契约）与「执行错」（\(\hat{c}=c\)，模型没把它认对的契约做对）。当模型父节点违反契约约束（轴绑定不成组、连乘码重复、顺序非法、三元组写不齐）时：

\[
\varphi_v(o_{\mathrm{Pa}(v)},x,\hat{c})=\bot.
\]

**约束违反在局部节点截断，不向深层传播。** 依据：浅层违约后深层推理大概率矛盾不自洽，确定性系统无法为矛盾前缀构造自洽全局解释，只能认定深层受上游传播影响。

## 3. 故障诊断设计

### 3.1 错误模式

识别是同一能力的两个深度，执行和数理是后面的能力。类名是英文关键词的缩写，不再用 E 代号。

| 类 | 能力 | 含义 |
| --- | --- | --- |
| DIR | 识别·直接 | 契约写明映射，读出来即可（Direct） |
| RSN | 识别·推理 | 契约只暗示路线，要理解才能选中（Reason） |
| EXE | 执行 | 认出之后照着做（Execute） |
| ALG | 数理 | 做的时候算错（Algebra） |
| RES | 残差 | 未建模，无注入（Residual） |

契约类 = 识别（DIR + RSN）+ 执行（EXE）。DIR 测能不能读对契约，RSN 测能不能根据契约想对路线，EXE 测想对之后能不能做对。ALG 不依赖契约，只读已经写好的中间量，因此不受上游契约错误影响。

### 3.2 故障实例库

| 类 | 键 | 一行代表 |
| --- | --- | --- |
| DIR | 每条写明映射的识别契约 | 一条直接识别错 |
| RSN | 每条需要推理的路线（≥2 空） | 一条推理识别错 |
| EXE | 每个派生父空 | 一个父空写错（见证=被最多计算器接受的错文） |
| ALG | 每个数理空 | 一个矩阵/向量/表达式上的数理错（单一滑移作见证） |

**口径**：故障定位在"答案写错的空"，不在"读到错的子节点"；子节点的读取是传播，交给递归并集，不另立行。

### 3.3 二值 D 矩阵与模糊组

D 矩阵采用标准故障签名矩阵（Fault Signature Matrix, FSM）的二值支持层语义：

\[
D_{f,m}\in\{0,1\},\qquad D_{f,m}=1\iff \text{故障 }f\text{ 会影响到测点 }m,
\]

即「会不会变」的支持关系，而非「变成什么值」的预测。在确定性系统 + 显式依赖图的前提下，这一二值支持关系由依赖图可达直接给出（零注入）：

\[
D_{f,m}=\mathbf{1}[m\in\mathrm{Reach}(f)],\qquad
\mathrm{Reach}(f)=\mathrm{desc}(\mathrm{Direct}(f)),
\]

其中 \(\mathrm{Direct}(f)\) 为故障 \(f\) 直接写入的测点集，\(\mathrm{desc}(\cdot)\) 为依赖图后代闭包。模糊组按二值支持列归并：同一空/契约的类标签重复（DIR/RSN/EXE 双登记）不是真模糊，应合并（一空一条根）；异空同 reach 才是真模糊，需加测点劈开。诊断中真正用到的「值」来自 \(\varphi_v\) 对模型真实错值的条件重算（§3.4），与 D 矩阵的二值支持层是两回事。

### 3.4 局部重算与五类分类

条件局部重算 \(\tilde{o}_v=\varphi_v(o_{\mathrm{Pa}(v)},x,\hat{c})\)（在模型认知契约 \(\hat{c}\) 下重算），局部一致性：

\[
\mathrm{LC}(v)=\mathbf{1}[o_v\equiv_v\tilde{o}_v].
\]

两根轴分开：**忠实轴**（\(o_v=\tilde{o}_v\) vs \(o_v\ne\tilde{o}_v\)，其中 \(\tilde{o}_v\) 在认知契约 \(\hat{c}\) 下重算）用于读数（忠实 vs 局部偏差）；**确定性轴**（\(\varphi_v\) 有值 vs \(\bot\)）用于可归因性（因果 vs 关联）。

五类 = 答案对错 × 可归因性（确定性）+ 忠实基线：

| 答案 | 可归因性（确定性） | 分类 |
| --- | --- | --- |
| 对 | 忠实（父全对） | 一致性正确 |
| 对 | 可归因（\(\varphi\) 有值，过程有错） | 可追溯答案遮蔽 |
| 对 | 不可归因（\(\varphi=\bot\)，矛盾） | 随机性正确（未诊断） |
| 错 | 可归因（\(\varphi\) 有值） | 可归因错误 |
| 错 | 不可归因（\(\varphi=\bot\)） | 不可归因错误 |

**可归因性 = 确定性轴（\(\varphi\) 有值 vs \(\bot\)），与忠实轴解耦。** 局部执行偏差（EXE）是因果根——即使 \(o_v\ne\tilde{o}_v\)（LC=0），只要 \(\varphi_v\) 有值，错误仍沿规则确定性传播，故 DIR、RSN、EXE、局部偏差都是因果。可追溯答案遮蔽合并了"确定性掩盖"（\(o=\varphi=g\)、父错）与"不忠实的正确"（\(o=g\)、\(o\ne\varphi\)）：二者都是答案对、过程有错、但系统未退化随机。归因强度：一致性正确（无误）；可追溯答案遮蔽（因果·被遮蔽）；随机性正确（关联）；可归因错误（因果）；不可归因错误（关联）。

### 3.5 错测点的候选集（递归保守归并）

诊断层的第一步产出**候选集**，不是冲突集。每个错测点 \(m\)（位于节点 \(v\)）先看该字段与 \(\varphi_v\) 是否一致：

- 一致：只收祖先里的故障；
- 不一致、没有局部规则，或 \(\varphi_v=\bot\)：本空的注入行与祖先故障并在一起。

祖先故障 \(f\) 要同时满足两件套才进入候选集：注入点全部落在 \(v\) 的严格祖先里，且二值可达集盖住这个测点。可达集来自图，不用预测值。

\[
f\in\mathcal{F}(m)\iff
\begin{cases}
\mathrm{Inj}(f)\subseteq\mathrm{Anc}(v)\ \land\ m\in\mathrm{Reach}(f), & \text{字段与 }\varphi_v\text{ 一致},\\[4pt]
\bigl(v\in\mathrm{Inj}(f)\bigr)\ \lor\ \bigl(\mathrm{Inj}(f)\subseteq\mathrm{Anc}(v)\ \land\ m\in\mathrm{Reach}(f)\bigr), & \text{不一致、无规则或 }\varphi_v=\bot.
\end{cases}
\]

\(\mathcal{F}(m)\) 是超集。递归归并所有错误祖先，不因中间答对而截断：中间答案等于金标时，分不清过程已经恢复，还是可追溯答案遮蔽。因果和关联的故障都收进来。每个错测点一个候选集，这就是该测点「可能根」的全集，不存在多个冲突集要同时打中。

### 3.6 可归因 / 关联切分

第二步把候选集按路径的确定性切开，不求极小碰集。对 \(f\in\mathcal{F}(m)\)，看注入点到 \(v\) 的路径：

\[
f\in C(m)\iff \text{路径上每个 }\varphi\text{ 都有值},
\]

\[
f\in R(m)\iff \text{路径上某处 }\varphi=\bot.
\]

\(o\ne\varphi\) 不改变这一判定。\(C(m)\) 是可归因（因果）：规则在模型这次写下的答案上已经确定。建模系统不再把库中见证文写回金标重放；那一步只是把同一个 \(\varphi\) 换一组输入再算一遍。与真实模型的匹配程度由 LLM 会话重放测量。\(R(m)\) 是关联：证据链在矛盾处断裂。规则没跑起来、又没有看到 \(\bot\) 的候选留在未解开。

| 子集 | 含义 |
| --- | --- |
| 可归因 \(C(m)\) | 路径无矛盾。确定性已由模型答案上的 \(\varphi\) 给出 |
| 关联 \(R(m)\) | 路径上出现 \(\varphi=\bot\)，证据链断裂 |
| 未解开 \(U(m)\) | 无规则或无法评分，且路径上没有 \(\bot\) |

诊断层不做极小碰集。经典 Reiter 的「冲突集 + 极小碰集」是在线诊断引擎，从症状反推最小异常组件集；这里候选集已经是超集，切分靠确定性轴，不靠碰集基数。最小修复集归因果层（§3.7），上界是该终点的全部上游节点，与 \(\mathcal{F}(m)\) 不是同一对象。

### 3.7 反事实核与不可分解度

目标 \(t\) 的反事实修复核：

\[
K^\star(t)=\arg\min_{S\subseteq\mathcal{F}}|S|\ \text{s.t.}\ y_{-S}\equiv y^\star.
\]

不可分解度 \(\delta(t)=|K^\star(t)|\)。搜索上界是目标 \(t\) 的全部上游节点：从 1 元增到把这些节点全部改回金标，停在最小的能恢复终点的那一档。全部上游都正确之后终点仍不恢复，才是修不好，不再因为超过 2 元就留空。\(K^\star(t)\) 与诊断层的候选集 \(\mathcal{F}(m)\) 分开：前者问「改回哪几处金标，终点才恢复」，后者问「这个错测点的可能根里，哪些还能被确定性解释」。一个空上的多条库内候选在修复里仍是一个节点。系统侧反事实（确定性重算）与模型侧反事实（重新调用模型）分开报告。多个最小核报集合与大小分布。

### 3.8 设计审计

- **latent**：目标直接因子中没有独立测点的个数（隐藏错误来源）；
- **alias**：不同因子赋值在某测点产生相同值的对数（值反解不开）。

## 4. 关键环节（流程）

### 4.1 三层评测流程

```text
设计层 ──► 诊断层 ──► 因果层
构造系统    归因错误    量化影响
```

- **设计层**：拆子问题、定目标、定参考规则与测点、构造故障实例库、图可达审计（算二值支持层与模糊组）、审 latent/alias；
- **诊断层**：解析模型答案、算残差、五类分类、候选集（递归保守归并）、可归因/关联切分；不做极小碰集；
- **因果层**：反事实修复、算不可分解度、危害度/发生度/传播深度三榜。

### 4.2 诊断流程（可执行）

```
1. 全局扫矛盾 φ_v=⊥，标记下游保守标签
2. 逐题局部重算 φ_v(o_父)，按答案对错 × 可归因性归成五类：
   → 对，父全对，φ 有值     ：一致性正确
   → 对，过程有错，φ 有值   ：可追溯答案遮蔽
   → 对，链上 φ=⊥          ：随机性正确
   → 错，链上 φ 都有值      ：可归因错误
   → 错，链上 φ=⊥          ：不可归因错误
   o=φ 还是 o≠φ 不改变这五类。
3. 错测点的候选集：字段与 φ 一致则只收祖先故障；不一致、无规则或矛盾，则本空注入行 ∪ 祖先故障。祖先故障须注入点 ⊆ 严格祖先，且二值可达集盖住该测点。这是超集，不是冲突集
4. 可归因/关联切分：路径上 φ 处处有值 → 可归因；某处 φ=⊥ → 关联。不在建模系统上重放见证文，也不求极小碰集
5. 因果层的最小修复集 K*(t)：上界是该终点的全部上游节点，从小搜到全体改回金标 → 不可分解度、危害度三榜。与诊断候选集不是同一对象
```

### 4.3 三层指标

| 层 | 指标 | 回答 |
| --- | --- | --- |
| 设计 | 可检测性、FIR、模糊组、latent、alias | 数据集能不能诊断 |
| 诊断 | 覆盖率、未认定率、因果/关联率、传播深度/广度、答案遮蔽率、随机性正确率、不可归因率 | 错误能不能被解释、多强 |
| 因果 | 发生度、影响范围、CR、不可分解度、危害度 | 哪些错误危害最大 |

危害度、传播深度、发生度分三榜报告，分歧本身是结论。

## 5. 结论性陈述

本设计将工程契约从隐含背景提升为**数据生成、参考执行、模型推理共同使用的显式输入**；通过契约与骨架分离，确定性程序在多种契约组合下自动生成过程金标；通过在图中设细粒度测点并做契约条件化局部重算，区分节点正确性与前缀条件下的局部执行一致性；通过递归保守归并，以及路径上是否出现 \(\varphi=\bot\)，把归因分为因果（系统仍可确定性推理）与关联（系统进入矛盾）；通过反事实核与三榜，量化错误影响。**方法核心是把"契约遵循"从隐式目标变为显式、可观测、可归因的评测对象。**
