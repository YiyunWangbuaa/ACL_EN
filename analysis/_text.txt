3  方法（Method）
本文提出一个面向异构工程契约的过程级评测框架，把「工程契约遵循」作为显式、可观测、可归因的评测对象。工程推理与一般算术或证明推理的关键区别在于：正确答案是契约敏感的（随契约可变）——它由题面声明的一套工程契约（坐标轴指向、角度正方向、变换约定、旋转顺序、安装方式、符号约定）所决定。同一物理场景、同一计算流程，只要契约字段改变，正确答案就会系统性改变。因此工程推理的核心能力不只是「算对」，而是「准确识别契约条件，并一致性地遵循契约推导出正确答案」。
现有过程级评测大多只区分「步骤对/错」（process supervision）或「最终答案对/错」，无法回答三个更细的问题：(i) 一个错误是「没读懂契约」还是「读懂了却执行错」；(ii) 一个「最终正确」的答案，其过程是可靠地正确，还是带着可追溯的遮蔽（过程有错、答案碰对），还是矛盾下的随机命中；(iii) 某个上游错误对最终目标的影响是因果的还是仅仅相关。本框架把评测数据从传统的「题目 + 参考答案」提升为「可诊断的系统模型」：每个任务被建模为一个确定性系统（依赖图 + 局部规则 + 契约），LLM 在该系统中作为待诊断的黑盒组件——我们不假设其内部结构，只观察它在各测点上的输出，并依据系统模型做故障隔离、错误归因与错误传播路径分析。这一「系统建模」的类比贯穿全篇：评测数据从一份份孤立的问答，变成一台可被诊断的仪器；「模型为什么错」从后验猜测变成一个可计算的诊断问题。方法分三层：设计层（构造系统、审计可诊断性）→ 诊断层（归因错误）→ 因果层（量化影响）。
3.1  任务形式化：契约、骨架与目标
一道工程任务分解为三元组：
T = (x, c, G)
物理场景 x：物理场景（飞机模型、相机布置、机械臂构型），描述「世界是什么」。
工程契约 c = (c_1, …, c_K)：工程契约，一组有限的约定/定义字段（坐标轴指向、角度正方向、变换约定、旋转顺序、安装方式、符号约定），描述「题面要求遵守什么规则」。
逻辑骨架 G = (V, E)：逻辑骨架，一个有向无环图（DAG）。节点 v ∈ V 是一个待回答的步骤或答案字段，边 (u → v) 表示 v 的推导使用 u 的输出。
核心设计：契约与骨架分离。对同一场景和骨架，可系统改变契约字段而不必重写推理流程：
T_c = (x, c, G)。
契约之所以要作为独立系统变量，是为了模拟真实工程中异构契约并存的处境：对同一物理实体，不同约定（坐标系、正方向、旋转顺序、安装方式）会给出系统性不同的正确答案。把契约单独抽出后，我们就能生成「反常识」的契约条件（例如轴向向后为正、反装、非标准旋转顺序），真实考察 LLM 对契约的理解与应用能力，防止它依赖训练分布中的先验约定对答案做直接模板匹配。契约同时进入模型提示与参考执行程序，使「是否遵循契约」成为可测量性质：模型若回落到默认约定，就会被显式观测。
3.2  推理图与测点
为什么要显式建模推理图与测点：契约遵循是 LLM 的内化能力，无法由目标问题对错反映出来；它与 LLM 的计算能力、语义理解、任务规划能力相耦合，且契约遵循本身是综合能力——先「识别契约」（读对契约 + 按契约想对路线），再「执行契约」。这些能力只呈现在隐含的中间推理步骤里，因此必须设置显性的、针对性的问题节点来暴露相应的能力缺陷。
每个参考流程表示为带契约条件的有向图：
G_c = (V, E, {φ_v}_{v∈V})
其中 V 是答案节点集；E ⊆ V × V 是推导依赖边，(u → v) ∈ E 表示 v 的推导直接使用 u 的输出；φ_v 是节点 v 在契约 c 下的局部规则——「给定父节点值与契约，v 的答案应是什么」。

3.3  契约条件化的确定性数据生成
数据由三个功能模块的确定性程序生成（无模型调用、无标注噪声）。三者以「契约 → 骨架 → 执行」的顺序协同：契约实例化器把契约 c 展开为题面中的工程定义与方法要求；骨架生成器按 (x, G) 把它切成逐步问题并标注依赖；契约条件化执行器沿骨架执行局部规则，产出金标轨迹。三者共享同一份契约对象 c 与骨架 G，保证题面、依赖、金标三者一致。
1. 契约实例化器（contract instantiator）：c → 题面中的工程定义与方法要求。
2. 骨架生成器（skeleton generator）：(x, G) → 逐步问题及其依赖。
3. 契约条件化执行器（contract-conditioned executor）：在 c 下沿骨架执行局部规则，生成金标轨迹。
局部计算规则依赖契约与父节点值（生成金标用正确契约 c）：
g_v = φ_v( g_Pa(v), x, c )。
金标轨迹与目标量：
τ* = ( g_{v_1}, …, g_{v_{|V|}} )，      y* = Target(τ*)。
题面、金标、目标统一由 q = Gen(x, c, G) 与 τ* = Exec(x, c, G) 生成。
契约组合实例化。契约组合空间 Θ ⊆ C_1 × ⋯ × C_K，每个 θ ∈ Θ 生成：
q_θ = Gen(x, θ, G)，      τ*_θ = Exec(x, θ, G)。
保持物理实体与目标不变、只改契约，生成结构可比、契约不同的评测实例。关键点：金标不是「从标准答案变换得到的标签」，而是该契约条件下完整执行骨架的结果——「改契约」与「换标签」有本质区别：前者改变的是推理过程本身的合法性条件，后者只是改变对错标签。
两层计算与契约认知重构。确定性程序包含两个层级的计算：
金标层：用金标父节点、正确契约 c 执行 φ_v，输出自洽标准结果。
局部计算层：用模型实际父节点、模型认知契约 ĉ 执行 φ_v，输出模型前缀下的条件结果。
契约认知重构是本方法的关键：局部计算层不直接按正确契约执行父节点，而是先从模型在识别测点（DIR/RSN）上的回答重构出模型实际认知到的契约 ĉ（例如由模型写下的坐标轴三元组推断其认知的手性，而非读金标的手性），再在 ĉ 下执行：
õ_v = φ_v( o_Pa(v), x, ĉ )。
这样才能区分「识别错」（ĉ ≠ c，模型忠实执行了错误契约）与「执行错」（ĉ = c，模型没把它认对的契约做对）。当模型父节点违反契约约束（轴绑定不成组、连乘码重复、顺序非法、三元组写不齐）时：
φ_v( o_Pa(v), x, ĉ ) = ⊥。
约束违反在局部节点截断，不向深层传播：浅层违约后深层推理大概率矛盾不自洽，确定性系统无法为矛盾前缀构造自洽全局解释，只能认定深层受上游传播影响。这一「局部截断」是本方法的重要设计决策。

3.5  可诊断性审计：二值 D 矩阵（图可达）
D 矩阵采用标准故障签名矩阵（FSM）的二值支持层语义：D_{f,m} ∈ {0,1}，D_{f,m}=1 ⟺ 故障 f 会影响到测点 m——它是「会不会变」的支持关系，不是「变成什么值」的预测。本方法直接从确定性系统的依赖图计算这一支持层（零注入、零重算）：
D_{f,m} = 1[ m ∈ Reach(f) ]。
该方法由模型故障诊断中的结构可诊断性分析启发迁移而来：在确定性系统 + 显式依赖图的前提下，「能否影响到」是纯图结构性质，因此只需一次图遍历即可得到全部故障-测点支持关系，避免了逐实例注入重算的冗余与大规模遍历成本。
由此，D 矩阵定位在数据审阅（设计）阶段，是一个辅助设计者设计题面测点的工具：它回答「当前测点能否检测、隔离每类错误，以及应当在哪些节点补测点」。需强调：D 矩阵只承载二值支持层，不承载任何预测值；诊断中真正用到的「值」来自 φ_v 对模型真实错值的条件重算（见 3.6），两者是两回事，不能混为一谈。

「可归因性」是确定性轴（φ 有值 vs ⊥），与忠实轴解耦。局部执行偏差（EXE）是因果根：即使 o_v ≠ õ_v（LC=0），只要 φ_v 有值，错误仍沿规则确定性传播，因此 DIR、RSN、EXE、局部偏差都是因果。可追溯答案遮蔽合并了原来的「确定性掩盖」（o=φ=g、父错）与「不忠实的正确」（o=g、o≠φ）：二者都是答案对、过程有错、但系统未退化随机，都可追溯到具体故障。
（LLM 视角：这一步对应「过程监督」中「步骤正确性」的严格化，且更进一步——它把「最终答案对/错」与「过程能否被确定性解释」两个维度交叉，得到完备且不重叠的五类；「正确」不再是一团，而是拆成忠实正确、可追溯遮蔽、随机命中三档。）
3.7  归因：候选集、可归因/关联切分
递归保守归并。不因「中间节点正确」而截断归因。对每个错测点 m（位于节点 v），先看该字段与 φ_v 是否一致：一致则只收祖先里的故障；不一致、无规则或 φ_v=⊥ 则本空注入 ∪ 祖先故障。祖先故障须注入点落在 v 的严格祖先内，且二值可达集盖住该测点。由此得到候选集（超集），而不是冲突集：
F(t) = { 局部错 at t } ∪ { w : w ∈ Anc(t), o_w ≠ g_w }。
中间「正确」无法区分「因果链恢复」与「可追溯遮蔽」，因此不假设恢复，递归归并所有错误祖先（用精度换完备性）。这与「找到第一个错步就停」的归因不同——那种做法会漏掉被遮蔽的上游错误。
可归因/关联切分。对候选根 w 到目标 t 的路径，判据是确定性（链上是否存在 φ=⊥），不是忠实（LC）：
w ∈ C(t)  ⟺  链 w→t 无矛盾（所有 φ 有值，确定性传播）；
w ∈ R(t)  ⟺  链 w→t 存在矛盾（某处 φ=⊥，非确定性）。
DIR、RSN、EXE、局部偏差都是可归因（局部错是根，照样确定性往下传）；只有 φ=⊥ 的矛盾才判关联。候选集按此切成三块：

诊断层不做极小碰集（那是在线诊断引擎从症状反推最小异常组；这里候选集已是超集，切分靠确定性轴）。完备性由超集保证（可归因 + 关联都收进来，不漏）；精度由可归因子集保证；诚实性由关联子集保证——「这条链在确定性处断了」本身是结论，不能假装它没断。最小修复集归因果层（3.8）。
3.8  反事实修复核与不可分解度
目标 t 的反事实修复核：
K*(t) = argmin_{S ⊆ F} |S|   s.t.   y_{−S} ≡ y*。
即：把哪些上游错误改回金标之后，目标 t 才恢复金标，且改的个数最少。搜索上界是目标 t 的全部上游节点。不可分解度 δ(t) = |K*(t)| 度量「终点错误是单个根因造成的，还是多个根因纠缠造成的」。K*(t) 与诊断层候选集 F(t) 分开：前者问「改回哪几处金标终点才恢复」，后者问「可能根里哪些还能被确定性解释」。
系统侧反事实（确定性重算：改上游 → φ 重算）与模型侧反事实（重新调用模型：把上游槽位替换成金标再问下游）分开报告。二者一致时，才能说「系统内的传播因果迁移到了模型的可见行为层」；不一致处（随机性、提示敏感、其他混杂）单独量化。多个最小核报集合与大小分布，不压缩成单点。
设计审计：
latent：目标直接因子中没有独立测点的个数（隐藏错误来源）。
alias：不同因子赋值在某测点产生相同值的对数（值反解不开）。
latent 与 alias 是「可诊断性」的前置审计，本身不保证可检测/可唯一归因。
3.9  三层评测流程
设计层 ──► 诊断层 ──► 因果层构造系统    归因错误    量化影响
设计层：拆子问题、定目标、定参考规则与测点、构造故障实例库、图可达审计（算支持层、分两类模糊组）、审 latent/alias。
诊断层：契约认知重构、解析模型答案、算残差、五类分类、候选集（递归保守归并）、可归因/关联切分。
因果层：反事实修复、算不可分解度、危害度/发生度/传播深度三榜。
诊断流程（算法形式）：
算法 1  过程级诊断输入：模型答案 o，依赖图 G_c，局部规则 φ，契约认知重构器输出：五类标签、候选集、可归因/关联切分、最小修复核1. 契约认知重构：由识别测点回答重构模型认知契约 ĉ2. 逐节点局部重算 õ_v = φ_v(o_Pa(v), x, ĉ)，记录忠实轴与确定性轴读数3. 五类分类：答案对错 × 可归因性（链上是否有 φ=⊥）+ 忠实基线4. 错测点候选集：字段与 φ 一致→只收祖先故障；否则本空注入 ∪ 祖先故障；    祖先须注入点 ⊆ 严格祖先且可达集盖住该测点（超集，不是冲突集）5. 可归因/关联切分：路径 φ 处处有值→可归因；某处 φ=⊥→关联；无规则且无 ⊥→未解开6. 因果层最小修复核 K*(t)（上界 = 终点全部上游）→ 不可分解度、危害度三榜

方法小结（核心主张）
本方法把工程契约从隐含背景提升为数据生成、参考执行、模型推理共同使用的显式输入；通过契约与骨架分离，确定性程序在多种契约组合下自动生成过程金标；通过契约认知重构，在模型认知契约下做局部重算，区分「识别错」与「执行错」；通过二值 D 矩阵做可诊断性审计，通过递归保守归并与确定性判定（路径上是否出现 φ=⊥）把归因分为可归因（确定性传播）与关联（矛盾）；通过反事实核与三榜量化错误影响。方法核心是把「契约遵循」从隐式目标变为显式、可观测、可归因的评测对象。
