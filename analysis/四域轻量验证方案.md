# 四域轻量验证方案

> 目标：在 wind_tunnel / aerodynamics / computer_vision / robotics 四域上，把已定稿的故障诊断流程跑通，验证方案可行。轻量 = 每域一个代表样本、每层一个最小断言、一个脚本串全流程、不跑模型、不跑 AI 级会话分叉。

---

## 一、轻量边界（明确砍掉什么）

| 不做 | 理由 |
| --- | --- |
| 全量稿件 | 每域取一个代表样本（自答前缀）即够验证管线通 |
| AI 级会话分叉 | 需调用模型，太重；管线正确性用系统侧验证即可 |
| 核搜索上界 | 该终点的全部上游本地故障；超过 2 元继续搜，全体仍失败才未解开 |
| 多轮采样 | 单次观测足以验证流程跑通，不做统计区间 |

---

## 二、四层验证步骤

每层一个检查点 + 一条合格线。全部通过即"跑通"。

### 第 0 层：基座自检（生成器 + 计算器）

| 项 | 内容 |
| --- | --- |
| 入口 | 各域 `stage0_check` / `pipeline_check`（金标回归） |
| 检查点 | 空注入 = 金标，即 \(\varphi_v(\text{金标父})=g_v\) 对所有节点成立 |
| 合格线 | 金标差分空、零差分；退出码 0 |

### 第 1 层：设计层（数据集可诊断性）

| 项 | 内容 |
| --- | --- |
| 入口 | `signature.evaluate/report` + `audit_composers.audit` |
| 检查点 | det=1 行数、FIR、模糊组数、latent、alias |
| 合格线 | det=1 行数 > 0；模糊组计数非空；latent=0（或标出待修）；alias=0（或标出碰撞） |

### 第 2 层：诊断层（错误归因）

| 项 | 内容 |
| --- | --- |
| 入口 | `conflict_diagnosis.explain_observations`（五态 + 递归保守 + 因果/关联） |
| 检查点 | 五态分类是否产出、覆盖率、未认定率、因果/关联率 |
| 合格线 | 五态至少能触发部分（非全空）；覆盖率 > 0；未认定率合理（不必为 0）；因果计数 > 0。没有 \(\varphi=\bot\) 时关联可以为 0 |

### 第 3 层：因果层（影响评价）

| 项 | 内容 |
| --- | --- |
| 入口 | `t_final.minimal_fixes` + `rank_harm` |
| 检查点 | 每个错误终点的修复核、频率/深度/危害度三榜 |
| 合格线 | 每个错误终点有核（单因素/2元/≥3）或标记未解开；三榜各自有排序、分歧可见 |

## 五、验证"方案可行"的判据

跑通只证明管线能转；"方案可行"还要看三条性质是否在四域都成立：

1. **可诊断性**：每域 det>0、模糊组可计数、latent/alias 已审——说明四域都能被构造成可诊断系统；
2. **可归因**：五态分类能覆盖观测、覆盖率>0、确定性错误记为因果——说明四域的错误都能被归因；
3. **可解释影响**：每错误终点有核或标未解开、三榜有排序——说明四域的错误影响能被量化。

三条在四域都成立，方案即验证可行。
