# GNNVerifier_Graph-based Verifier for LLM Task Planning

## 一句话
该文构造了两种保持"接口类型可执行性"（规则层不变）的扰动——Wrong Tool（只换节点工具符号，依赖结构与顺序不变，可被单点本地替换修复）与 Missing Step（删/压节点，改依赖图结构，必须靠图上消息传递定位并经边插入修复），并用实验证明 LLM 序列化读取时两类错误都检不出、纯规则验证只治类型违例，唯有图感知验证能同时修复表示层与结构层错误。

## 核心思想
1. 计划建模为有向属性图 G_r=(V,E)：节点=工具调用实例（工具 t_i + 步骤文本 s_i），边=执行顺序与依赖约束；依赖图 G_tool 由 I/O 类型兼容性导出（out∩in≠∅），即规则系统 R。错误被二分：Wrong Tool（节点层，表示类）与 Missing Step（DROP/COMPRESS，结构类）。
2. LLM 是序列模型：把计划序列化为步骤序列/JSON 后只能逐句孤立判断，被流畅叙述误导，检不出跨步结构关系（类型不匹配、缺中间步、断依赖）；验证与定位须由 GNN 在图结构上消息传递完成（structure-native 评估）。
3. 训练监督由对 ground-truth 计划图的可控扰动自动生成，且所有扰动强制保持接口类型连通（满足 R 但语义错误）→ 判别器学到"规则满足 ≠ 计划正确"。
4. 修复是受约束的本地编辑：仅在图分 S_r<τ_G 时触发，最多 3 处编辑、每处 Top-3 候选、单次重试，且仅当新图分更高才接受——有限预算的本地重写即可修复两类错误。

## 支撑框架的位置
- **(a) 强支撑（经验证据）**：Wrong Tool 扰动只替换节点的工具符号——步骤文本 s_i、依赖边、顺序、类型连通全部保持不变（相当于只改 θ、不动 (G,R)），75% 概率从语义近邻 N_K(t_i) 采样以模拟真实规划器的"细粒度混淆"；raw 计划实测含大量 Wrong Tool 错误，经 replace_on_node 本地重写后计数大幅下降（图 3，四数据集降幅最大的错误类之一）。→ 直接支撑"表示层扰动真实存在、LLM 确实犯错、且可被有界本地重写修复"。
- **(b) 弱支撑（仅'等价性检验困难'一侧，无有界性证明）**：所有扰动强制满足接口类型连通，即"规则层等价"却语义错误；规则式验证器 VeriPlan（对照依赖图逐边查约束）检不出 Edge Fail（类型相容但语义错的边），ReAct+UltraTool Acc 仅 34.47 vs GNNVerifier 44.20；在 GNN4Plan 规划器下 Dependency Error 已被图约束清零，但 Missing Tool/Edge Fail 依旧存在——说明 R-满足不是正确性判据，规则层等价性检验不足。注意：文中修正的"有界"只是固定启发式（≤3 编辑、单次重试），不构成任何可证明的有界规范化。
- **(c) 强支撑（依赖结构影响 LLM）**：论文采纳并验证 GNN4Plan 结论"LLM 无法准确辨识计划图结构"；消融 w/o GNN（去消息传递改 MLP）使验证反馈有害——GNN4Plan 规划器下 Acc 从 Raw 41.20% 掉至 33.00%（HuggingFace）、57.00%→50.00%（Multimedia）；相对最优基线 VeriPlan 的增益在边层最大（ReAct 平均 l-F1 +20.47%、Acc +35.19%），错误集中在依赖/结构层。
- **(d) 强支撑（序列化 vs 图结构）**：LLM 验证器"逐条读孤立步骤"被流畅叙述误导、检测不到跨步结构错误；计划须序列化为步骤序列+JSON，跨步依赖在序列表示中丢失，须转回图（边编码执行顺序与依赖）交给 GNN 评估；长上下文提示稀释注意力、加重幻觉。GNN 直接在图上游走，绕开序列化瓶颈。
- **(e) 强支撑（预算改善表示层不改善结构层）**：加推理/反思预算不修复结构——Refine（LLM 自反修正）多组设置差于 Raw（Direct+HuggingFace Acc 31.20 vs 34.20）；ReAct 推理步更多但链接指标更差（Raw l-F1 HuggingFace 53.35 vs Direct 55.27），却从 GNN 结构反馈获益最大（Acc +35.19%）；DailyLife n-F1 已近饱和（≈97%）而 l-F1/Acc 仍大幅提升，剩余错误集中在结构层。在同预算（均恰好一次修订）下，图感知反馈比 LLM 式验证多修复两类结构错误。

## 边界
- 计算模型限于工具增强任务规划：已知工具集+依赖图，训练依赖 ground-truth 计划图（自监督扰动生成标签），验证器是学习式判别模型而非形式化验证器，无 soundness/completeness 保证。
- "结构"指静态工具调用 DAG+接口类型约束：无执行反馈（文中明确列为未来工作）、无循环/条件分支、无数值/符号推理（不涉及坐标/单位/正方向类 θ 内容）。
- 扰动只覆盖 Wrong Tool 与 Missing Step 两类故障模式，不能外推到未建模的错误族；修正有界性是工程约束而非证明。
- "Wrong Tool=表示扰动"是类比：工具身份在文中形式上属图的一部分；只能说该扰动保持依赖结构、顺序与类型规则不变而仅改节点内容。
- 数据集为 TaskBench 三域（HuggingFace/Multimedia/DailyLife）+ UltraTool（3000 训练/500 测试），结论限于 GPT-4o 与 Qwen3 两类骨干 LLM。
